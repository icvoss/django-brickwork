{% comment %} Stat band (04-interfaces.md section 4d): a display-scale metric band. Structural, consumed via {% include %} (BR-BW-MKT §4d structural-include doctrine). Composes _stat.html's tile shape per BR-BW-MKT-004 (a marketing component reuses an existing primitive rather than reimplementing it), laid out here as a display-scale band rather than the dashboard KPI row patterns/dashboard.html's bw-stat-grid uses. Required context: none. Optional context: heading (str): the section heading. stats (list of dicts): {value, label, trend?, trend_label?}. Each is passed straight through to _stat.html, so the standing VIZ-002 / BR-BW-TPL-007 rule holds unchanged here: a trend without a trend_label is a template-authoring defect in the same class as bw_button's icon-only/aria_label pairing (_stat.html enforces this at its own render, not duplicated here). An empty (or omitted) stats list renders the heading alone (or nothing, if that too is empty). stats is list-shaped, so it has no flat-kwarg spelling (#98): a Django template cannot build a list inline, so supply it from context (the view, or a wrapper template's own data). A template-authored page with static stat content (the ADR-056 compose-it-yourself shape) instead includes brickwork/components/_stat.html directly once per stat: its contract is already flat strings (label, value, trend, trend_label), which is exactly what this band forwards per item. States: none of its own beyond whatever each forwarded _stat.html tile carries (trend direction, loading); every tile in the band renders at size="lg", fixed, never a per-item choice.
