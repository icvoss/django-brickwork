- **A page viewed at exactly 640px now gets the wide-side styles**
  (icvoss/django-brickwork#220, ADR-079). The form grid's single-column
  collapse previously applied through 640px inclusive (`max-width: 40rem`);
  the breakpoint-token migration rewrites it as the exclusive `width < sm`,
  consistent with Tailwind's own `sm:` convention, so at that one exact
  width forms move from the stacked single-column layout to the multi-column
  layout. No other width changes behaviour; this was a convention alignment,
  not a bug fix, and pages at 639px and 641px render exactly as before.
- **`dist/brickwork.css` is recompiled through Tailwind's full pipeline**
  (icvoss/django-brickwork#220, ADR-079 section 5a). Introducing the `@theme`
  breakpoint block switches the build from near-passthrough to a full compile
  pass, so the shipped file is reshaped throughout (banner, reformatting,
  merged selectors) and every `color-mix()` value gains an `@supports`
  fallback wrapper (roughly 95 of them): a static baseline declaration sits
  before each `@supports` block, and the `color-mix()` declaration moves
  inside it. For consumers this is behaviourally invisible in any browser
  that supports `color-mix()`; in browsers without `color-mix()` support,
  the previously bare `color-mix()` declaration was invalid and ignored,
  and those browsers now apply the static baseline colour instead, which is
  a rendering change in those browsers. Anything diffing or post-processing
  the shipped CSS byte-wise must re-baseline.
