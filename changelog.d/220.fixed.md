- **`--bw-breakpoint-sm/md/lg/xl` ship as real tokens, replacing 15 hardcoded
  media queries, and fix a live boundary bug** (icvoss/django-brickwork#220,
  ADR-079). SHL-014 ratified `--bw-breakpoint-*` bridged via `@theme inline`,
  which never shipped because the mechanism cannot work: a media query
  cannot resolve `var()`. The tokens are now emitted as literal values in
  `tokens.css` and as a second, plain `@theme` block (not inline) in
  `tailwind-theme.css`, both generated from one new token source
  (`breakpoint.tokens.json`), and the 15 internal call sites across
  `shell.css`, `components.css` and `marketing.css` reference them via
  `--theme()` range syntax instead of a repeated `40rem`/`48rem`/`64rem`
  literal. This also fixes a live defect: `max-width: 48rem` and
  `min-width: 48rem` rules both matched at exactly 768px, so the shell's
  sidebar collapse and `_data_table`'s stack mode could apply at the same
  width another component's desktop layout was already active. Two exact
  pixel widths change behaviour as a result, verified by browser
  measurement: at 768px, exactly one side of the corrected boundary now
  applies; at 640px, the form-grid single-column collapse no longer applies
  (the old inclusive `max-width: 40rem` is now the exclusive `width < sm`,
  consistent with Tailwind's own `sm:` convention). The honest limit:
  overriding `--bw-breakpoint-*` changes a consumer's own Tailwind build,
  not brickwork's already-compiled `brickwork.css`, which changes only on a
  package rebuild.
