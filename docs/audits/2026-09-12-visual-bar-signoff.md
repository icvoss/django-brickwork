## 6. Blockers for a pass

Ordered by how much they cost the claim.

1. **Phone navigation across every family.** #520, #519 and #523. Three of the
   eight surfaces cannot be navigated at 375px with the package's own examples;
   on five more the menu button is invisible. Nothing else on this list matters
   as much.
2. **Forms.** #521. A textarea that renders at single-line height is a defect
   any consumer meets on their first form. While fixing it, give one scorecard
   form help text and a bound error so the Forms axis is actually tested.
3. **Table craft.** #522. Numeric alignment is not expressible through the
   component's vocabulary, and it shows on half the surfaces.
4. **S8 and the phone tile row.** #525. Point the harness at the shipped ops
   report or dense list, or amend section 3 in a dated revision. Stack the
   weighted tile row below the app breakpoint.
5. **Fixture credibility.** #524 and #500. Fix the broken logo asset and the
   non-existent token, populate the feature, stat, FAQ and table data to the
   shape the components advertise, then re-render. Until then Density, Spacing
   rhythm and Section cadence on S1, S5 and S6 stay "not evidenced" rather
   than pass.

A re-score after those five may pass. It should be a fresh independent render
from the tagged tip, not an edit of this file.

## 7. Evidence provenance

Recorded because it changes how much weight the prior scorecards can carry.

- No package-only PNGs existed anywhere in the repository or its worktrees when
  this review opened. `docs/audits/_stills/` held only its README, and the only
  captured set on disk was the northline brand leg. The `2026-09-12-phase3`
  directory that the Phase 3 re-score cites as "32 PNGs" was gone. Stills are
  gitignored by design, so this is expected housekeeping rather than
  misconduct, but it does mean the Phase 3 rows could not be checked against
  the images that produced them. This reviewer regenerated the package-only set
  from the same harness and the same substrate instead.
- Regeneration: `a11y/generate_visual_bar_fixtures.py` (package-only, 16
  fixtures, manifest reports 3.18.0), then `a11y/visual_bar_capture.mjs` with
  `VISUAL_BAR_STILLS_DATE=2026-09-12-phase5-review` (32 PNGs).
- The fixtures load no JavaScript: the capture inlines `brickwork.css` and the
  `{% static %}` script tags do not survive a `file://` render, so every still
  is a no-JS render. That is a fair test of this package, whose shells use
  `<details>` disclosures rather than script, and it is how #519 and #520 were
  found. It also means no JS-dependent behaviour anywhere in the scorecard has
  ever been exercised by these stills, which no prior pass stated.
- Defects were confirmed by computed style and geometry under Playwright with
  `javaScriptEnabled: false`, not by eye alone. Each issue records the measured
  values and, where it is a cascade collision, the byte offsets of the
  competing rules.
- Kit comparison was look-and-idea only, from prior familiarity with the
  priority-1 and priority-2 panel kits and the local Forge stills under the
  umbrella `docs/_examples/forge-ui-kit-site/` (present, ten files). No kit
  markup, class string or structure was copied, and Forge leads no row.
